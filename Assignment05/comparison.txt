In the C++ program, the operations that have side effects are `set`, `remove`, and `load` because they change the contents of the `Store`, while `save` has a side effect because it writes to a file. The command loop also has side effects because it reads input and prints output. In the OCaml program, `save` and `load` have side effects because they interact with files, and the command loop has side effects because it handles console input and output. The OCaml functions `set`, `get`, `delete`, `list`, and `transaction` can reasonably be considered pure because they do not modify anything outside themselves. Mutable state in the C++ implementation exists mainly inside the `Store` class, where the `std::map` can be changed by functions such as `set`, `remove`, and `load`. In the OCaml implementation, the store itself is immutable, so operations create new stores instead of changing the existing one. RAII helps control side effects in C++ by connecting an object's behavior to its lifetime. Our `Transaction` class creates a backup of the store, and if `commit()` is not called, the destructor automatically restores the backup when the transaction goes out of scope. Immutability helps control side effects in OCaml because an existing store cannot be changed unexpectedly, so an earlier version can always be kept and used again. Rollback also works differently in the two implementations. C++ has to save a backup and restore it if the transaction fails, while OCaml can simply continue using the original store because it was never modified. OCaml can retain an earlier state without explicitly copying the entire map because its `Map` is a persistent data structure that can share unchanged parts between different versions. Overall, the immutable OCaml model makes basic transaction rollback easier to express because the original state remains available automatically, while C++ uses mutation, backups, object lifetime, and RAII to manage rollback. This shows that C++ generally controls side effects through objects, ownership, scope, and lifetime, while OCaml reduces side effects by using immutable values and keeping operations such as file and console I/O at specific points in the program.
